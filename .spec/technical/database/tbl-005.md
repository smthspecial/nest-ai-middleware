# ai_pending_actions

Durable confirmation and recovery state for the optional write milestone. This PostgreSQL table is created by `003_actions` when a host adopts that milestone.

## Columns

| Column | Type | Constraints |
| --- | --- | --- |
| action_id | uuid | Primary key. Generated server-side. |
| application_key | varchar(100) | Required installation namespace. |
| tenant_ref | varchar(128) | Required verified tenant or host-defined single-tenant namespace. |
| owner_ref | varchar(128) | Required verified subject reference. |
| conversation_ref | varchar(128) | Conversation reference if present. Has an independent retention lifecycle. |
| tool_name | varchar(64) | Required registered tool name at proposal time. |
| tool_revision | varchar(128) | Required registration or schema revision. |
| validated_args | jsonb | Required immutable, bounded arguments. Host governs access and encryption. |
| operation_key | uuid | Required. Unique with `application_key`. Stable across recovery. |
| state | varchar(24) | Required. `pending`, `claimed`, `completed`, `failed`, `rejected`, `expired`, or `outcome_unknown`. |
| revision | integer | Required positive action revision. Initially one. |
| created_at | timestamptz | Required. |
| expires_at | timestamptz | Required deadline for first approval. |
| claimed_at | timestamptz | Set by the atomic approval transition. |
| purge_after | timestamptz | Required retention deadline for reconciled records. |
| safe_result | jsonb | Optional bounded result for authorized replay. |

Scope claims by application, owner, and tenant. Claim only an unexpired `pending` action and recheck the current tool and policy before dispatch. Increment the revision and insert an audit event in the same transaction as the state update. Reconcile ambiguous outcomes under the original operation key. Keep unresolved actions available to the authorized recovery process. The business service owns atomic mutation deduplication.
