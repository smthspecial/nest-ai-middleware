# Register my model and selected NestJS services

As a NestJS developer, I can bind my existing model and select explicitly decorated methods from my services so that AI access is limited to capabilities I register.

## Acceptance criteria

- I can register with `forRoot()` or inject the initialized model and policy into `forRootAsync()`.
- My existing Nest services retain their DI ownership. Explicit module, `@AiService()`, and `@AiTool()` declarations govern registration. Missing opt-ins, absent permission labels, and ambiguous registrations stop bootstrap with a useful diagnostic.
- A deterministic custom model example type-checks against the published contract and runs offline.
