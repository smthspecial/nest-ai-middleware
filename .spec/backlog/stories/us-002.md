# Execute an authorized read in my application's request context

As a NestJS developer, I can invoke an authorized read using the caller's Nest request context so that the same service dependencies, identity, and tenant restrictions apply.

## Acceptance criteria

- Valid data reaches only the approved read method. Denied permissions, validation errors, and expired requests yield zero calls. A write declaration fails at bootstrap.
- A host example demonstrates `REQUEST` injection, additive `@AiPermissions()` requirements, a replaceable tenant-aware policy, safe output, and typed failures.
- The published package and types work in an independent consumer fixture. Tests demonstrate context isolation, cancellation before dispatch, and the documented limit on cancellation after dispatch.

Requirements [FR-003](../../requirements/fr/fr-003.md), [NFR-001](../../requirements/nfr/nfr-001.md), and [NFR-002](../../requirements/nfr/nfr-002.md).
