# Persist conversation history under verified ownership

**Phase 4.** Let a host opt into a conversation store with separate content retention and owner- and tenant-scoped reads. Keep stateless requests supported.

## Acceptance criteria

- A verified owner can continue a stored conversation after restart. Model context is built from bounded stored turns. An expired, absent, or inaccessible ID yields the same safe error.
- Concurrent turns use optimistic revisions so they cannot overwrite or reorder committed history. A failed append reports a conflict without automatically re-running the model.
- The store applies the configured content projection and retention. It can be enabled independently of run bookkeeping. See [conversation tables](../../technical/database/tbl-003.md).
