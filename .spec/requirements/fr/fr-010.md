# Persist conversation history under verified ownership

A host can opt into conversation history and run bookkeeping together by supplying `database.adapter`. Stateless requests can pass their own history.

## Acceptance criteria

- A verified owner can continue a stored conversation after restart. Context includes every saved turn in order. An absent or inaccessible session ID yields `SESSION_UNAVAILABLE`.
- Within a session, the adapter grants an exclusive run lease. An overlapping request receives `SESSION_BUSY`. Saving a turn and releasing the lease are atomic.
- Save the final text returned to the caller with the user message, tool names, and tool IDs. Release the lease when a run fails.
- List and read sessions only for the verified subject and tenant. Page the stored transcript and keep database retention under host control. See [conversation storage](../../technical/services/srv-001.md#conversation-lifecycle).
