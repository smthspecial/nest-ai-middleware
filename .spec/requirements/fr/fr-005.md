# Support an authenticated host AI endpoint

**Phase 2.** In the reference application, register a Nest controller for `POST /ai`. The host applies its auth and validates the message and optional session ID. The library propagates the trusted request context through the orchestration loop.

## Acceptance criteria

- The host chooses the path, global prefix, and native Nest guards in its own module. The registered `AiModule` exposes an injectable `AiChatService`.
- Test global guard ordering, ordered authentication and authorization route guards, guard-specific handler metadata, and short-circuiting on denial. Verify the identity resolver sees the authenticated request and the request-scoped service receives the original context.
- Service and method guards run before tool definitions go to the model and again before each invocation.
- The controller rejects malformed or oversized requests and absent or invalid host identity before reaching the model. It aborts the orchestration on client disconnect or timeout and returns a sanitized HTTP error envelope when the connection remains open.
- Input and output prompt checks are enabled by default and can be switched independently. A rejected check returns a generic HTTP 500. If a database adapter is configured, the middleware stores the rejection code for backend inspection.
- The reference app can return the answer and the middleware's run and session IDs. Session access requires the verified subject and tenant. See [host HTTP integration](../../technical/arch/arch-002.md#http-and-response-envelope).
