# Expose a configurable authenticated AI endpoint

**Phase 2.** Mount one Nest controller route, `POST /ai` by default. Accept a message and optional correlation ID, apply host authentication, and propagate the trusted request context through the orchestration loop.

## Acceptance criteria

- Custom static route paths and the host's global prefix work under both synchronous and asynchronous registration on supported HTTP adapters. Both registration forms accept native Nest `authenticationGuards` and `authorizationGuards` with dependency injection and access to the real HTTP execution context.
- Test global guard ordering, ordered authentication and authorization route guards, guard-specific handler metadata, and short-circuiting on denial. Verify the identity resolver sees the authenticated request and the request-scoped service receives the original context.
- Discovery policy runs before any tool definitions are sent to the model. A discovery grant does not satisfy the separate execution check.
- The controller rejects malformed or oversized requests and absent or invalid host identity before reaching the model. It aborts the orchestration on client disconnect or timeout and returns a sanitized HTTP error envelope when the connection remains open.
- Successful responses include `conversationId`, `message`, and validated text blocks. A client-provided correlation ID gives access to no stored history or pending actions in Phase 2. See [the HTTP contract](../../technical/arch/arch-002.md#http-and-response-envelope).
