# Execute authorized reads through existing NestJS providers

**Phase 1.** A trusted caller invokes the exported `AiToolExecutor` with a tool name, arguments, caller identity, and a Nest context ID. The executor applies the registry lookup, execution policy, strict runtime validation, authorization, DI resolution, and result rules.

## Acceptance criteria

- Authorized calls use the existing singleton or the provider instance bound to the caller's actual Nest context. Repeat calls in a context see the same scoped dependency tree. Different contexts remain isolated.
- Unknown tools, malformed arguments, denied service guards, missing caller identity, and pre-dispatch cancellation yield zero business-method calls. Service and method guards run in the original Nest request scope.
- Output projection, schema validation, timeout, and tool errors produce bounded, documented outcomes. Raw service errors remain inside the application boundary. See [the authorization specification](../../technical/auth/auth-001.md).
