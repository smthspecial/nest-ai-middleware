# Track AI runs, tool outcomes, and model usage

Persist AI bookkeeping alongside conversation history through one host-initialized adapter. SQLite is the local default choice. PostgreSQL and MongoDB adapters use the host’s own client.

## Acceptance criteria

- Configuring an adapter enables conversation persistence and bookkeeping. Each adapter initializes its own storage layout and touches only plugin records. The host manages database connections.
- Each admitted run records timestamps, status, and stable error codes. Generation and tool events record outcome and duration, along with model-reported usage or tool and invocation IDs as applicable.
- Records survive restart. Bookkeeping stores metadata, while conversation turns retain screened text. Bookkeeping write failures are best effort and can emit a sanitized diagnostic through the host logger. See [bookkeeping configuration](../../technical/services/srv-001.md).
- A host service can read run status, accepted output, and committed events for an authorized session owner through `AiRunReader`.
