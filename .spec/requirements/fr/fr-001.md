# Configure a provider-independent NestJS module

**Phase 1.** A host application supplies an initialized `AiModel`, a class allowlist, and its authorization policy. The module exposes `forRoot()` and `forRootAsync()` and accepts an injected async factory with the usual Nest module imports.

## Acceptance criteria

- Synchronous and injected asynchronous configuration each initialize the same exported executor. The supplied model object is preserved and its initialization remains the host's responsibility.
- Invalid model shape, missing policy, invalid limits, and malformed allowlist fail during bootstrap with actionable diagnostics.
- A custom adapter can express messages, tool results, multiple tool calls, optional usage, an abort signal, and declared capabilities without importing a provider SDK. A model may explicitly declare that tool calling and structured output are unavailable. See [the protocol](../../technical/arch/arch-002.md).
