# Register explicitly allowlisted tool methods

**Phase 1.** Build an immutable in-memory registry at startup from allowlisted Nest classes marked with `@AiService()` and their own methods that declare `@AiTool()` and `@AiArgs()`. The registry holds compiled validation and private execution bindings alongside model-facing definitions.

## Acceptance criteria

- An allowlisted class without its own `@AiService()` fails bootstrap. A marked class outside the allowlist and an undecorated method on a marked, allowlisted class are both absent from the registry.
- Reject duplicate tool names, unsupported method signatures, invalid schemas or metadata, and missing or ambiguous Nest bindings during startup.
- Build each tool's effective requirements from its class hierarchy and method `@AiPermissions()` declarations. Require at least one effective permission per tool. Reject any write or confirmation declaration in the initial read-only release.
- Registry lookup uses the declared tool name. Public tool metadata contains only schema and selection information. See [provider binding](../../technical/adr/adr-001.md).
