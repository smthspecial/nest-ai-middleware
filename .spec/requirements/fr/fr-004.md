# Orchestrate bounded model-driven read workflows

**Phase 2.** Rank visible tools by deterministic matching over names, descriptions, tags, and usage hints with stable tie-breaking and a configured candidate limit. Expose a ranking extension point after authorization filtering. Provide the model with available definitions, collect approved calls, and return sanitized tool results to the model as context.

## Acceptance criteria

- A fake model uses the result of one call to request a dependent call in the next round, then provides a final reply. Multiple calls in a valid batch yield one result per call, linked by ID and appended in request order.
- Validate the entire batch envelope, call IDs, and remaining call budget before starting it. Reject malformed envelopes and duplicate IDs without partial dispatch. A validly addressed call with bad arguments or an unavailable tool yields a bounded result error. The model can recover from an individual read error within the same run budget.
- A round can call only tools offered in that round. When there are no authorized candidates, permit a text reply with no tools. Candidate retrieval can incorporate bounded context across rounds and must apply the same visibility rules every time.
- Execute batches sequentially by default. Parallel reads require explicit host metadata that permits concurrent use and an independent batch. Dependent work uses later rounds. Cap read concurrency and preserve the same context ID.
- An adapter lacking declared tool calling returns a clear startup error for the tool-enabled HTTP module. No implicit parsing fallback is used. Hard limits apply to each interaction. See [NFR-002](../nfr/nfr-002.md).
