# Orchestrate bounded model-driven read workflows

The host's model receives the decorated tool definitions that the caller is authorized to use. The model can answer directly or request one or more tools and use their results in a later round.

## Acceptance criteria

- Discover eligible tools once at the beginning of every chat model loop. The model can choose among the offered tools or answer directly. The tool list is empty when the caller has no eligible tools.
- Validate the entire batch envelope, call IDs, and remaining call budget before dispatch. Reject malformed envelopes and duplicate IDs without partial dispatch. When output screening is enabled, check the whole batch before its first tool runs.
- Run tool calls in order in the original Nest request context. Recheck tool guards and validate each call's schema before invocation. Return a stable result code for an unavailable tool, denied call, or schema error so the model can continue within the run budget.
- A dependent call can use results from an earlier model round. Apply the run and tool budgets described in [NFR-002](../nfr/nfr-002.md).

Semantic ranking and independent-read parallelism are future work.
