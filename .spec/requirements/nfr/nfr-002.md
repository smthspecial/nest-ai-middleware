# Bound execution time and resource use

**Phase 1 onward.** Enforce finite time and size limits at the layer that owns the operation. Reject invalid configuration at startup. An absolute request deadline covers all discovery, model calls, dispatch, and response composition from Phase 2 onward. Use the remaining budget for each child operation.

| Limit | Proposed default | Starts in |
| --- | --- | --- |
| Tool execution deadline | 10 seconds, including policy and DI resolution | Phase 1 |
| Serialized tool arguments and result | 16 KiB arguments and 64 KiB per result | Phase 1 |
| HTTP interaction deadline and message size | 30 seconds and 16 KiB of message text | Phase 2 |
| Model calls and tool-call attempts | 10 model calls and 20 tool-call attempts per run | Phase 2 |
| Candidates and read concurrency | 12 offered tools per model round and up to 4 concurrent calls when explicitly enabled | Phase 2 |
| Model transcript | 256 KiB serialized including tool definitions | Phase 2 |

## Acceptance criteria

- Stop dispatch when the request is cancelled, any enforced limit is reached, or the remaining time is insufficient. Count rejected tool-call attempts toward the cap and check the whole batch against the remaining budget.
- Check JSON size and nesting with bounded traversal. Limit work before schema validation and before forwarding data to a model or client. Set transport body limits before application-level parsing where supported. The host owns deployment-wide traffic quotas and rate limits.
- Propagate abort signals and enforce deadlines even when an asynchronous adapter ignores cancellation. A dispatched call may outlive the response deadline or commit a side effect. Abort prevents later dispatch and requires cooperation from already-running code. Synchronous code that blocks the event loop can delay timer delivery.
